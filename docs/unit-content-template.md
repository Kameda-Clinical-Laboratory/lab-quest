# ユニット原稿テンプレート(調査・判断・報告・発展の作り方)

`docs/series-authoring-guide.md`(全体方針)・`docs/series-roadmap.md`(シリーズ一覧)を前提に、
**1ユニット分の原稿を実際に埋めていくための作業用テンプレート**。埋め終わったら
`content/series/_template.mjs`に流し込み、`scripts/push-series.mjs`で投入する。

参考実装: `content/series/bio-hemolysis.mjs`(溶血、大項目4-A)。迷ったらここを見る。

---

## 0. 元ネタ(骨子案から埋める)

- 大項目・中項目: 例)4 検体の性状と測定妨害 / 4-A 溶血
- 対象小項目(2〜4個。多すぎる場合はユニットを分ける): 例)a成因 b溶血指数 c偽高値項目 d偽低値項目 e許容限界 f報告方針
- 症例の一言(付録Bにある場合はそれを流用): 例)「溶血疑いのK高値を、報告前にどう扱うか決める」

---

## 1. 会話(第1幕・自由記載)

- **分量**: 3〜5行
- **型**: ①技師が違和感/依頼を提示 → ②実習生が反応 → ③技師が「まず何を確認すべきか」を示唆(講義・調査へのブリッジ) → ④(任意)今回決めることを一言で締める
- **背景(backgroundId)**: `labhall`(臨床検査室ホール)/`ward`(病棟)/`conference`(カンファレンス室)/`corridor`(廊下)/`prologue`(プロローグ・アスピア)/`epilogue`(エピローグ・アスピア)/`fin`(Fin.)から場面に合うものを選ぶ

```
話者A: (違和感の提示)
話者B: (反応)
話者A: (講義/調査への橋渡し)
話者A: (今回決めること)
```

## 2. クエスト発生(第2幕・固定、編集対象は unit.title / unit.requestLine のみ)

- **title**: 短い体言止め。何が届いた/何が起きたか(例:「赤く染まった検体」)
- **requestLine**: 1文。状況+今回何を決めるか(例:「届いた検体がうっすら赤い。このまま報告していいか確認する」)

## 3. 講義(第3幕)

- **分量**: 200〜500字、2〜3段落
- **型**:
  1. 現象の定義・成因
  2. 影響の方向性(対になる2方向があれば両方に言及。例: 偽高値/偽低値、上がる/下がる)
  3. 施設差・許容限界・報告手順への言及(調査・判断・報告へのブリッジ)
- **bridge**: 「教科書で〇〇を確認し、キーワードを入力してください」の1文

## 4. 調査(第4幕・1ユニットにつき1〜3枚のカード)

**カードを分ける基準**: 小項目が「対になる2方向」を持つなら分ける(例: 偽高値/偽低値、採取順序/持ち込み影響)。単一の知識確認なら1枚でよい。3枚を超えるなら、対象小項目が多すぎるのでユニット分割を検討する。

### 調査カードの型(puzzleType、2026-08 第4幕リニューアル)

単調な選択式の繰り返しを避けるため、カードごとに型を選べる。省略時は`board`。

| puzzleType | 概要 | 追加で必要なフィールド |
|---|---|---|
| `board`(省略時のデフォルト) | 候補から該当するものを選ぶ(従来型) | なし。`choices`のみ |
| `order` | 手順・時系列のカードを正しい順に並べ替える | `steps: string[]`(正しい順序で定義。`choices`は使わない) |
| `match` | 左列(略語・症状等)と右列(正式名称・原因等)をタップして組み合わせる | `pairs: {left, right}[]`(`choices`は使わない) |
| `cloze` | 文中の空欄にひらがなで解答を入力する穴埋め型(2026-08追加)。講義本文を歯抜けにして調査に統合する用途を想定 | `text: string`(空欄は`{{blank}}`リテラルで表す)、`blanks: {answer: string, altAnswers?: string[]}[]`(出現順に対応。`answer`はすべてひらがな) |
| `cipher`(非推奨) | 正解すると「文字の欠片」(`fragmentChar`)を1つ入手し、後で並べ替えてフラグワードを完成させる | `fragmentChar`(1文字)。ユニット側に`flagWord`(下記)が必須になる。**実機検証の結果、謎解きとして機能しないと判明したため新規シリーズでは使わない**(`docs/series-authoring-guide.md` §3.5参照) |

**まず`board`のまま、対立仮説を立てて消去させる形で面白くできないか検討する**(`docs/series-authoring-guide.md` §3.5)。それでも表現しにくい謎解き(手順の並べ替え・組み合わせ・読解の穴埋め)がある場合に`order`/`match`/`cloze`を使う。`cipher`は使わない。型を混在させても構わない(例: 1枚目board、2枚目cloze)。

`match`のペア・`order`の手順も、単純な用語↔定義の丸暗記対応にしない(§3.5の原則と同じ理由 — 一瞬で解けてしまうものは謎解きにならない)。可能なら「根拠↔支持する仮説」「手順の中で紛らわしい前後関係」のような、一瞬考える必要がある組み合わせにする。

### フラグワード(cipher型を使うユニットのみ)

cipher型カードを1枚でも使うユニットは、ユニット直下に`flagWord: { answer: '...' }`を必ず書く。`answer`の文字を1文字ずつ分解した集合が、そのユニット内の全cipherカードの`fragmentChar`の集合と過不足なく一致していなければならない(順不同。実習生が並べ替えて完成させる語そのものになる)。

例: 「偽高値になる項目」正解→`み`、「偽低値になる項目」正解→`わ`、「溶血の程度」正解→`け` → `flagWord: { answer: 'みわけ' }`(見分け)。具体的な言葉選定はシリーズごとに個別に決める(全シリーズ共通のルールはない)。参考実装: `content/series/bio-hemolysis.mjs`(3枚とも`cipher`型)。

### カード1枚につき(puzzleTypeに関わらず共通)

| 項目 | 内容 |
|---|---|
| 対応する小項目 | 骨子案のa/b/c… |
| clue名(key) | 「〇〇の△△」形式。既存clueと同名なら自動的に再利用される |
| purpose | なぜ確認するか。症例の文脈に紐づける(「〇〇が疑われる検体を前に」等) |
| howTo | どこで確認するか(教科書・配布資料・観察) |
| choices(board/cipherのみ) | 3〜6択、correct 1〜4個(複数正解可)。紛らわしい項目を最低1〜2個distractorに入れる |
| text/blanks(clozeのみ) | 講義相当の本文に`{{blank}}`で空欄を作り、`blanks`に出現順で正答(すべてひらがな)を並べる。判定は完全一致のため、読み方の揺れ・類義語(例:「振とう」↔「振動」)が想定されるならその空欄の`altAnswers`に別解を追加する(2026-08、clinical-content-reviewer指摘を受けて追加。理解していれば別解でも正解として通す) |
| demoHint | モック正解例(スタッフ確認用) |

## 5. 判断(第5幕・title固定「判断」)

- 1問。`requiredClueKeys`は**最初の/最も直接的な**調査カードの手がかりのみ
- **prompt型**: 「(役職)「(状況の再掲)。次はどうする?」」
- choices: 2〜3択、正解1つ
- **内容**: 初動対応(パニックにならず手順に沿って動けるか)

## 6. 報告(第6幕・title固定「報告」)

- 1問。`requiredClueKeys`は**そのユニットの全調査カード**の手がかり
- **prompt型**: 「では、最終的にどう報告する/対応する?」
- choices: 2〜3択、正解1つ
- **内容**: 施設差(◆)を意識した最終判断。**feedbackに必ず「施設ごとに基準/手順が異なるため、自施設の手順を優先する」旨を一言入れる**

## 7. 発展(第7幕・3〜6問)

構成の目安(bio-hemolysisの実績: 5問):

1. 講義の基本知識(単一選択)
2. 調査カード1の内容を国試形式で聞き直す(**複数選択可**)
3. 初動対応・最初の行動を問う(単一選択)
4. 調査カード2の内容を国試形式で聞き直す(**複数選択可**、カードが2枚以上あれば)
5. 判断/報告の考え方を一般化した設問(単一選択、「最も優先すべきは」型)

各問に`explanation`を必ず付ける。**単一選択のみで埋めない**(投資ビートで複数選択に慣れているぶん、発展でも1〜2問は複数選択にして出題形式を混ぜる)。

## XP配分の目安(bio-hemolysisの実績)

| 幕 | XP |
|---|---|
| 会話 | 5 |
| クエスト発生 | 5 |
| 講義 | 10 |
| 調査(1枚あたり) | 15 |
| 判断 | 15 |
| 報告 | 15 |
| 発展 | 20 |

調査2枚構成なら合計 5+5+10+15+15+15+15+20 = **100**が目安。1枚なら85、3枚なら115。

## 埋め終わったら

1. `content/series/_template.mjs`をコピーして`content/series/<stageId>.mjs`として保存し、上記で決めた内容を書き込む
2. `node scripts/push-series.mjs content/series/<stageId>.mjs --dry-run`で送信内容を確認
3. `STAFF_FULL_PASSWORD=<pw> node scripts/push-series.mjs content/series/<stageId>.mjs --publish`で投入・公開
4. 使い捨てテスト実習生で実際にクリックして通しで確認(CLAUDE.mdの手順どおり、TRAIN01/02には触れない)
5. 画面に影響する変更(新規シリーズの初回投入は該当)は`game-ui-ux-reviewer`のPASSまで確認する
