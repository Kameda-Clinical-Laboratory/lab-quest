# LAB QUEST 発表原稿（4分）

想定：図解1分 ＋ モック操作3分。読み上げはややゆっくり。  
操作は【】で示す。製品名は画面どおり **LAB QUEST**（Biochemistry and Immunology）。

## 事前準備

1. 図解を全画面表示（`creating-visual-explainers/output/lab-quest.html` があれば。無ければモックのログイン画面から開始してよい）
2. 別タブで `npm run dev` → http://localhost:5173/
   - 実習生：受講者コード `TRAIN01` / パスワード `1234`（ログイン直後のホームが理想）
   - スタッフ：別タブで `/staff/login` → `ops` まで進めておくと安心
3. ホーム上部のステータスバー（Lv・XPゲージ・図鑑）と、地図バナーのマスが見える位置にしておく

## Part A｜図解／狙い（約1分）

【図解、またはログイン画面の左イラストを表示】

臨地実習の朝、指導者はルーチンで手が一杯です。  
実習生は教科書を持っている。でも「いま現場で何を見て、どう判断するか」は、そばに先輩がいないと止まりがちです。

今日お見せするのは、その空白を埋めるWebアプリのモックです。  
名前は **LAB QUEST**。検査室を、冒険の拠点に見立てています。

一言でいうと、**実習カレンダーに沿ってシリーズを進め、途中は繰り越し、学んだ手がかりは図鑑に残し、最終日はクリアした範囲だけで確認テストを受ける**アプリです。

見た目はゲームです。中身は実習の運用に合わせています。  
午前はアプリで自習、午後は現場。指導者が毎回ゼロから教えるのではなく、事前に学習パックを組んで、当日は現場へ集中する——それが狙いです。

（図解を閉じ／最小化し、モックのタブへ）

## Part B｜モック操作（約3分）

### B-1 入り口とホーム（約55秒）

【ログイン画面】  
受講者コードとパスワードで入ります。スタッフは下のボタンから別入口です。

【「冒険を始める」→ ホーム】  
上がステータスバーです。名前とレベル、XPとスタンプのゲージ、そして **図鑑**。  
日付や何日目かは、すぐ下の地図バナーに出します。情報は二重にしない、という割り切りです。

【地図バナーのマスを指す／1つクリック】  
マスの数は、その実習生の実習日数です。進んだ日は点灯し、クリックで日付を切り替えます。静止画の飾りではなく、進捗そのものです。

山田さんのモックでは、前日分が残っていると **繰り越し** が出ます。  
その下に、本日のシリーズが並びます。

【8/12 のマスへ】  
シリーズゼロの日は、見学など「アプリなし」と出ます。学校ごとに日数も見学の入り方も違うので、カレンダーで本数を変えられるようにしています。

【8/11 に戻す】

### B-2 学びの型と図鑑（約70秒）

【「基礎知識」を開く】  
シリーズの中は、昔の「講義→一問一答」だけではありません。

流れはこうです。  
**会話で困りごとが開く → 短い講義 → 教科書や現場で調べる → 手がかりを使って症例を解く → 発展問題。**  
調べたものは、減点ゲーではなく、あとで使える装備になります。

【ヘッダーの「図鑑」を開く】  
入手済みの手がかりはここに残ります。未入手はシルエットです。  
指導者不在の午前でも、「何を調べて、何が分かったか」が積み上がる設計です。

【ホームへ戻る】

### B-3 管理者と最終確認（約40秒）

【スタッフログイン `ops`】  
実習生ごとにパスワードと **実習カレンダー** を組みます。0本なら見学日。必須の未割当は保存時に警告します。

【進捗】  
誰の必須が残っているか、今日のキュー、繰り越し、CBT素点を一覧できます。進捗は口頭ではなく、ここで追います。

【実習生に戻り、最終確認テストへ】  
合否はありません。**クリア済みシリーズの問題だけ**から組みます。  
理解度の換算は指導者。アプリが出すのは、評価の参考になる素点です。

### B-4 締め（約15秒）

こうなると、指導者が手を離せない午前でも、実習生は臨床寄りの課題を進められます。  
日数が違っても、カレンダーで組めば、同じ仕組みで回せます。

LAB QUEST は、まだモックです。これから中身を一緒に作り込みます。  
今日お伝えしたかったことは一つだけです。  
**忙しさを理由に、臨床の学びを止めない。**  
ご清聴ありがとうございました。
